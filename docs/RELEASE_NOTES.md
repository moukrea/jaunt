# jaunt 0.1.0-beta.18

This release refines bridge delivery after the second field test: a reply handed to a session that is waiting for it (`wait_seconds`) is no longer pushed into that conversation a second time; messages delivered to a Claude Code session assert the sender's permission class, so a Claude session that bypasses permission prompts accepts messages from a Codex session that bypasses them too without asking (Claude Code's own rule for its peers; otherwise it still asks, and `crossSessionInbound` in Claude's settings remains your choice); a home directory under version control is no longer taken as a project root; presence uses the shell's current directory. beta.17 consolidated the bridge after its first field use: a Claude Code or Codex session that is open in a jaunt shell on the project but has not registered yet (no prompt so far, hooks not yet trusted) is now announced as present and not yet reachable instead of being invisible, and the hook and MCP commands are installed as plain executables under the host's state directory (`bridge/hook-<runtime>`, `bridge/mcp-<runtime>`) so they run whether the runtime hands them to a shell or executes them directly. beta.16 fixed a beta.15 regression: runtime detection no longer runs at host start when the bridge is off, so the switch could stay hidden until a client asked; detection now runs at start and each time Settings opens. beta.15 made bridge identity independent of the runtime's environment: hooks and MCP tool calls are matched to the jaunt terminal they run in by process ancestry or by the controlling terminal itself, the host state directory is passed as an argument, integrations are re-applied when the host starts, and refused registrations are logged in `host.log`. On a fresh installation the Claude Code side reported "not started from a jaunt shell" although it ran in one; the root cause was not reproduced on the development machine, so every dependency on inherited variables and process parentage was removed. beta.14 fixed runtime detection for hosts running as a user service: `claude` and `codex` are now resolved the way jaunt shells resolve them (login + interactive shell, then well-known per-user install locations), so the bridge switch appears on such hosts. beta.13 introduced the **Claude Code ↔ Codex bridge**. When both `claude` and `codex` are installed on a host, Settings shows a single switch. Turned on, real Claude Code and Codex sessions started from jaunt shells on the same project automatically know about each other (as ordinary hook context: terminal, id, availability, how their workspaces relate) and can message each other's open conversation through the `jaunt_send` tool, at your request or on their own initiative. Messages arrive through each runtime's own inbox mechanism (Claude Code's per-session inbox, `codex queue`) with explicit provenance; replies are correlated; loops and rates are bounded. Turning the switch off removes every hook, MCP entry and allow rule jaunt added, refuses further sends and unblocks waiting sessions. Sessions already open join after their next restart or `/clear`; Codex asks once to trust the new hooks.

The bridge was validated end to end with the real runtimes (Claude Code 2.1.273, Codex 0.154.0): see [the bridge guide](BRIDGE.md) and [its validation report](BRIDGE_VALIDATION.md). The Claude Code inbox it relies on is versioned but not a documented public API; incompatible runtime versions are reported as such. The protocol has not undergone an independent security audit.

Host updates keep the improvements from beta.12 (pushed progress, expected-restart signalling, running-version truth, rollback, deferred auto-resume).
