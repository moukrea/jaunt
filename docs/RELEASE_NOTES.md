# jaunt 0.1.0-beta.13

This release adds the **Claude Code ↔ Codex bridge**. When both `claude` and `codex` are installed on a host, Settings shows a single switch. Turned on, real Claude Code and Codex sessions started from jaunt shells on the same project automatically know about each other (as ordinary hook context: terminal, id, availability, how their workspaces relate) and can message each other's open conversation through the `jaunt_send` tool, at your request or on their own initiative. Messages arrive through each runtime's own inbox mechanism (Claude Code's per-session inbox, `codex queue`) with explicit provenance; replies are correlated; loops and rates are bounded. Turning the switch off removes every hook, MCP entry and allow rule jaunt added, refuses further sends and unblocks waiting sessions. Sessions already open join after their next restart or `/clear`; Codex asks once to trust the new hooks.

The bridge was validated end to end with the real runtimes (Claude Code 2.1.273, Codex 0.154.0): see [the bridge guide](BRIDGE.md) and [its validation report](BRIDGE_VALIDATION.md). The Claude Code inbox it relies on is versioned but not a documented public API; incompatible runtime versions are reported as such. The protocol has not undergone an independent security audit.

Host updates keep the improvements from beta.12 (pushed progress, expected-restart signalling, running-version truth, rollback, deferred auto-resume).
